# 多层透明：多次采样投票选择实验 V10

日期：2026-09-14。基于 V9.1 冻结权重，只新增可选后处理与评估；不重新训练、不更改普通路线、不提升默认生产配置。

## 结论

投票已实现并完成验证、测试集对照。3 次严格投票能筛除不稳定的液面层候选，降低有输出子集的平均误差；代价是覆盖率降低。相同输出位置上的精度收益较小，按序列重采样的置信区间包含零，不能据此宣称投票已经解决多层透明或达到工业液深目标。5 次模式覆盖率更接近原方案，但收益很小；7 次和置信度加权未显示稳定优势。

本报告主指标是**相机视线方向的液面深度**，不是液面到容器底面的最终液深。容差为 `max(5 mm, 标注相机深度 × 2%)`，沿用旧 V9.1 评估以便比较；不能直接将此通过率当作液位工程验收通过率。表面代理指标也是标注参与计算的有符号深度残差中位数，不是部署时的真实平面拟合。

## 1. 层数过多的审计

现有模型最多产生 4 个候选分量，由存在概率表示是否活跃。无序分量编号不等于物理层身份。此前层数 MAE 只表示数量误差，不能判断是多估还是少估。

在本轮 486 个测试样本的有层标注位置上，以存在概率至少 0.5 计活跃层：

| 指标 | 结果 |
|---|---:|
| 真值平均层数 | 1.765 |
| 预测平均活跃层数 | 1.652 |
| 多估层数的位置比例 | 39.77% |
| 少估层数的位置比例 | 41.19% |
| 层数恰好相等的位置比例 | 19.04% |
| 活跃候选未匹配到容差内任何标注层的比例 | 52.05% |

最后一项包含真实层位置预测不准，不能全解释为虚假层。将相邻预测深度按 `max(5 mm, 深度 × 1%)` 直接合并，可把多估比例降至 8.63%，但少估比例升至 60.77%。因此没有把简单删层/合并层提升为正式方法；两个真实且靠近的界面也可能被合并。

## 2. 投票设计与安全边界

1. 单次推理仍使用 V9.1 的界面身份、存在/置信度和米制先验选择器。每个采样每个像素最多投一票，不让一个预测里的多个重复层贡献多票。
2. 采样次序固定：原图、水平翻转、垂直翻转、亮度乘 0.95、亮度乘 1.05、双向翻转、额外遮去 5% 原始深度。几何变换后将标量深度和掩码逆变换回同一图像坐标；不使用未校正的法向通道。
3. 按深度接近程度聚合，而非按分量编号投票。配对距离不超过 `max(5 mm, 两深度较小者 × 1%)` 才算同一深度模式；选获胜模式内的中位数，不跨不同物理层平均。
4. 简单相对多数票选择支持数最大的模式，票数并列时拒绝。严格模式至少要求全部请求采样的 60% 支持，即 3/5/7 次分别至少 2/3/5 票；弃权仍计入分母，并保留与原图先验的冲突拒绝。
5. 加权对照使用原选择器置信度累加模式得分，仍受最小票数、竞争模式和先验检查约束。
6. 同一输入不加变化地重复运行确定性模型，只会复制同一票；测试覆盖此反例。即使所有采样都一致选错层，也可能形成高一致度，因此一致度不能当作测量正确概率。

这属于**单帧测试时增强（TTA）**，不是多张真实独立照片、不是时序恢复，也不是多个不同模型的独立证据。亮度相近的采样尤其相关。真实多帧投票仍需位姿/光流对齐、动态液位与历史过期检查。本轮不扩展 95%-100% 失效期间的恢复优化。

## 3. 验证与冻结过程

- 开发：先用验证集每类 12 个样本检查实现，再用完整 481 个验证样本比较 9 条路径。
- 门限审计：旧训练选择器默认相对先验门限为 0.08，旧正式评估脚本为 0.008。初次探索使用前者，不能与旧报告比较。最终全部使用 0.008、绝对先验门限 0.02 m、拒绝倍数 3、置信阈值 0.5。
- 对齐后验证集单次基线复现：MAE 15.856 mm、AbsRel 2.917%、容差通过率 53.759%、有效像素覆盖率 52.095%，与旧 V9.1 报告一致。
- 在验证集确定 3 次严格投票作为优先检查的低误差方案，5 次严格投票作为接近原覆盖率的对照。然后冻结全部参数运行 486 个现有测试样本：透明 97、半透明 97、多层透明 163、复合 129。
- 测试含 188 个不同 sequence_id；相邻样本相关，像素更非独立样本。该划分未参与本轮调参，但不是全新未知领域盲测；历史项目其他训练/评估可能已使用同一测试域。
- 真值仅用于评分与层数审计，不参与模型采样、选层或投票。

## 4. 完整测试结果

有效像素覆盖率 = 输出且有有效真值的像素 / 全部有效真值像素；容差通过率的分母仅为输出且可评估像素。“全目标容差覆盖”同时惩罚缺失和不准，不应只看条件 MAE。

| 路径 | 相机深度 MAE/mm | AbsRel | 容差通过率 | 有效像素覆盖率 | 全目标容差覆盖 | 帧覆盖率 |
|---|---:|---:|---:|---:|---:|---:|
| 单次 V9.1 | 16.739 | 3.130% | 51.79% | 53.55% | 27.73% | 73.05% |
| 3 次相对多数 | 14.913 | 3.161% | 52.94% | 50.10% | 26.52% | 73.66% |
| 3 次严格投票 | 13.458 | 3.045% | 53.73% | 45.55% | 24.48% | 68.52% |
| 5 次相对多数 | 17.240 | 3.194% | 51.51% | 57.51% | 29.63% | 73.87% |
| 5 次严格投票 | 16.481 | 3.114% | 51.95% | 53.32% | 27.70% | 72.43% |
| 7 次相对多数 | 17.310 | 3.207% | 51.36% | 57.91% | 29.75% | 74.28% |
| 7 次严格投票 | 13.879 | 3.054% | 53.15% | 45.63% | 24.25% | 68.11% |
| 5 次置信加权严格投票 | 16.483 | 3.114% | 51.95% | 53.32% | 27.70% | 72.43% |
| 7 次置信加权严格投票 | 13.885 | 3.054% | 53.16% | 45.64% | 24.26% | 68.11% |

帧覆盖率要求至少 64 个预测输出点，不依赖真值数量。JSON 另保留旧版“任意一个像素有输出”口径与可评估率；两种口径不能混用。即便帧有输出，也不意味着支撑范围足够拟合可靠液面。

### 分场景：单次与 3 次严格投票

| 场景 | 样本数 | MAE/mm 单次→投票 | 容差通过率 单次→投票 | 有效像素覆盖率 单次→投票 |
|---|---:|---:|---:|---:|
| 透明 | 97 | 12.714 → 10.881 | 53.17% → 54.09% | 69.42% → 61.56% |
| 半透明 | 97 | 18.145 → 15.871 | 63.29% → 67.05% | 60.41% → 51.16% |
| 多层透明 | 163 | 19.641 → 14.778 | 47.90% → 50.07% | 55.42% → 46.68% |
| 复合 | 129 | 15.693 → 12.078 | 42.11% → 42.35% | 32.55% → 26.32% |

多层透明条件 MAE 降约 24.8%，但覆盖减少 8.74 个百分点。该类别 AbsRel 仍为 3.318%，容差通过率仅约 50%，不能宣布完成适配，更不能用它推导最终液深工程达标。

### 排除“只拒绝更多”的共同支持比较

在每种投票与单次方法都输出的同一像素上重新评分：

| 对照 | 单次 MAE/mm | 投票 MAE/mm | 单次通过率 | 投票通过率 |
|---|---:|---:|---:|---:|
| 3 次严格投票共同位置（全测试） | 13.593 | 13.438 | 53.02% | 53.74% |
| 5 次严格投票共同位置（全测试） | 16.541 | 16.484 | 51.85% | 51.95% |

多层透明共同位置 MAE 从 14.978 降至 14.727 mm。相较表中条件 MAE 的下降，这些直接修正收益很小：主要收益仍来自筛选不稳定点。对全测试 3 次方案按 sequence_id 成组进行 2000 次配对 bootstrap（种子 20260914），共同位置 MAE 差值“投票减单次”的 95% 区间为 [-0.344, +0.048] mm，包含零，不构成稳定直接改善的充分证据。

### 表面代理与尾部

全测试的有符号深度残差中位数代理，单次→3 次严格投票的 MAE 为 24.67→19.27 mm、P95 为 102.36→74.85 mm；多层透明分别为 31.10→24.34 mm、135.99→92.35 mm。输出子集不同且计算使用真值，不能作为最终液位精度或可部署平面算法的替代。

## 5. 延时与接入

RTX 5090，320×180，batch=1；每方法预热 5 次、测量 20 次。测试末尾模型常驻，数据已在 GPU：

| 路径 | P95/ms |
|---|---:|
| 单次模型加选择器 | 5.05 |
| 3 次严格投票 | 13.60 |
| 5 次严格投票 | 24.25 |
| 5 次加权投票 | 31.20 |
| 7 次加权投票 | 38.55 |

计时包含多次模型推理、变换和投票，不含相机采集、CPU 输入预处理、传输、平面拟合、位姿求解与 GUI。测量次数有限；这些数值只表明新增模块的计算开销可控，不证明整系统 P95 已满足 0.5 s。

新增接口（不修改现有默认 process）：

```python
from liquid_depth.models.layer_voting import predict_liquid_vote

model.eval()  # 已加载 V9.1 的 UniversalLiquidSurfaceNet
result = predict_liquid_vote(
    model, normalized_rgbd_batch,
    samples=3, weighted=False, min_fraction=0.6,
    confidence_threshold=0.5,
)
# 输入为已有训练编码的 B×5×H×W，深度通道采用 0.1-10 m 对数编码。
# accepted 是研究级像素选层结果，不是工业液深接受决定。
# research_only=True；agreement 是采样一致度，不是测量正确概率。
# rejection_code: 1 票数不足，2 竞争模式票数差不足，3 与原图先验不一致。
```

不建议无条件启用：追求低条件误差时可选 3 次严格模式；要求保持覆盖时保留原方案或测试 5 次模式。7 次与置信度加权暂不作为优先方案。当前 `predict_liquid_vote` 不负责跨帧同步、位姿对齐或最终工业安全拒绝，应置于现有几何/独立校验之前。
