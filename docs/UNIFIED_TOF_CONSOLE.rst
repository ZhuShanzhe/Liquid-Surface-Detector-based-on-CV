ToF 模块化统一入口与仿真展示软件
================================

版本：unified_tof_console_v1_20261019。此入口为可运行的实验展示版；
不替换已发布的人工场景选择正式版，不沿用正式版的通过率来证明自动选路。
目前只支持 ToF，未恢复结构光或主动双目。

模块与数据流
------------

::

  初始化：空槽 RGB-D + 独立尺寸/重力标定 + 材质确认
              └── 均匀透明/半透明：空槽 + 四帧已知液深的原始相位
  每帧统一 ToFObservation
      ├── RGB、深度图、时间、安装 ID
      └── 可选原始 AMCW 相位 [3频率, 4相移, H, W]
                    ↓
  空槽 ROI 裁剪 → RGB-D 多标签视觉分类头 + 可观测输入质量
                    ↓
  模块编排（只允许一个权威液深核心，不叠加多次测距修正）
      ├── 普通漫反射 → 原冻结对称几何核心
      └── 均匀透明/半透明 → 五帧先验 ToF 折射相位核心
                    ↓
  可选漂浮物最高高度：原 V8 的 ToF/V5 支路；不修改液深
                    ↓
  统一结果：液深、最高高度、模块表、输入质量、警告、延时

接口位于 src/liquid_depth/unified_tof.py；算法与软件界面互不依赖。
ToFInstallation 是固定安装的统一先验容器，ToFObservation 不接收任何真值字段。
不同材质不再使用不同 measure 参数列表；原始相位是可选数据通道，而非伪造的深度图替代品。
普通链路可以不提供相位；透明链路没有相位/五帧先验时明确报缺失，不静默回退普通链路。

应用边界与组合
--------------

* 普通漫反射、低照、眩光、部分缺失、不平整共用一个冻结液深核心。
  低照/眩光标签用于观测检查，并不凭空插入未经验证的增强网络或重复修正。
* 漂浮物视觉模块只影响最高高度。其是否启用与“是否识别出漂浮物”分开记录：
  标签阈值来自分类验证；最高高度启用阈值根据验证集的实际高度误差选择。
* 透明与半透明限于均匀液体、固定顶部相机、可见底部调制、无漂浮物遮挡的近似平面液面。
  折射率/消光/散射参数由五帧先验拟合，不由 RGB 分类概率代替。
* 仅研究现有标签的有限组合。普通液体的低照/眩光/缺失/起伏/漂浮物组合可在展示中运行，
  但组合结果标记为实验状态，不视为已获正式计量认证。
* 透明/半透明与漂浮物、非平整液面的组合未获验证：展示控件拒绝这种组合。
  外部统一接口默认也拒绝疑似冲突，除非初始化明确确认了均匀平整无遮挡应用范围；
  此时保留已确认物理链路并告警，而不是让不可靠分类标签任意更换数值算法。
* 不包含多层透明、多种液体叠层、强散射的透明链路、连续移动相机、超过 50% 的液面缺失适配。
  观测 ROI 缺失率不是隐藏的“真实液面缺失率”，二者不能混用。
* 保留超界数值与警告，不强制归零、不裁剪输出、不通过置信度删掉高误差帧。

初始化与实地迁移
----------------

展示软件调用 Blender 生成空槽，从空槽图像及独立仿真标尺、重力建立容器几何，
检查尺寸一致性；透明链路自动生成并拟合一空槽加四个已知液深的相位采集。
这些是仿真中已知的独立先验，不是当前测试液深；当前真值只在推理完成后读取，
供界面左列对照。加减液体时，相机相对于容器底面的位置和朝向固定。

这种自动初始化仅适用于演示。实地必须换成真实空槽图、真实标尺/重力/相机内参、
已知液深先验以及设备 SDK 的原始 AMCW 数据，不可把仿真真值当作现场可用信息。
RGB 三维外观由 Blender 生成；透明原始相位来自独立解析传输模型。
两者尚不是商业传感器的联合光谱数字孪生，不能据此宣称硬件精度已认证。

界面与启动
----------

在服务器仓库根目录（已有项目 Python 环境与 Blender）运行：

::

  LIQUID_PYTHON=/root/autodl-tmp/envs/liquid-depth/bin/python bash scripts/launch_scene_console.sh

本机建立隧道后访问 http://127.0.0.1:18765：

::

  ssh -N -L 127.0.0.1:18765:127.0.0.1:8765 -p 26663 root@connect.bjb2.seetacloud.com

服务只绑定服务器回环地址。不要改成无认证的公网监听。
先点击“初始化 / 重新标定”，再操作液位、照明、眩光、漂浮物数量、起伏、缺失比例，
点击“应用工况并测量”。切换液体自动重做先验。
左侧真三维网格与测量点云支持旋转、平移和缩放，估计液面单独显示。
右下分别显示实际与估计高度。仿真采集耗时和算法耗时分开报告，前者通常为秒级。
示例容器固定相机到底面 4 m、内高 1.5 m、半径 0.55 m；并非把算法量程限制为此值。

测试与已知不足
--------------

分类训练使用新生成的 36 个物理安装、864 张 Blender RGB-D 工况图，按完整安装分为
576 训练、144 验证、144 诊断测试图。另有独立种子生成的 12 安装、288 图分类测试。
分类标签的预测能力和端到端测量精度分开报告，不能用标签准确率代替毫米测量误差。

初期小网络版本存在材质混淆、小漂浮物漏选、不平整误报；相关失败结果保留。
独立 12 安装、144 帧几何组合试验中，仅 4 安装用于启用阈值校准，另外 8 安装为测试。
该试验暴露了旧核心在新组合和传感器代理上的大误差，不能以软件成功输出数值宣称组合达标。
原几何液深未改变，视觉开关前后逐帧液深一致，但最高高度仍有误选与长尾风险。
上一轮失败的空间支撑修复模块没有接入。本次不得据此覆盖原正式性能 PDF。

当前状态：统一输入、模块编排与展示交互已实现；自动选路与复合计量仍是实验功能。
发布前还需更充分的可观测性审计、独立逐组合计量测试及现场验证。
不要使用本控制台直接控制泵、阀、PLC 或安全联锁。

最终采用的分类头与测试结果
------------------------

采用 ImageNet 预训练 MobileNetV3-Small 编码器，空槽 ROI 图像裁剪与归一化深度特征，
仅训练末端编码块及小型多任务分类头。预训练权重来自 torchvision 官方权重地址，
运行时使用已打包的模型，不再联网下载。

新种子 202610192877、12 个物理安装、288 图的独立分类测试：

================ =============== ===============
标签             精确率          召回率
================ =============== ===============
低照             82.93%          94.44%
眩光             72.15%          79.17%
不平整           90.77%          81.94%
漂浮物           97.80%          82.41%
================ =============== ===============

材质三分类准确率 77.43%，全部标签同时正确率 68.06%。这些值不能作为液深准确率。
材质不能由图像无条件自动确认，因此保留一次性的初始化材质确认与物理先验绑定。
独立分类测试在选择模型/标签阈值之后才计算，没有用此结果再次修改阈值。

最高高度启用阈值在另一个开发队列的 4 个安装、48 帧上按实际高度 MAE 选定，
不等于分类标签阈值；这只是一轮初步启用校准，尚不构成正式自动选路认证。
该队列曾用于发现旧模型失败，其剩余测试部分现仅作为开发诊断，不再称为新独立最终验证。
漂浮物标签为真但视觉最高高度不获推荐时，继续保留原几何最高包络，并明确告警。
训练标签中的漂浮物工况以 12 个物体为主；界面允许 1--24 个是操作功能，
不表示各数量、大小和遮挡比例都已完成计量验证。几何组合开发试验的液深输出
开关前后完全相同，但 96 帧诊断测试中仅 93 帧出数、液深全帧通过率 75%，
不能以单场景旧报告的高通过率覆盖这些未通过的新组合结果。

初始化会预加载可选最高高度模型的权重，不把空槽当作漂浮物图像测量；
首次 CUDA 推理仍可能超过 0.5 s。持续测量、首次推理、模型初始化及 Blender
采集不是同一个延时口径。没有宣称所有工况的端到端刷新均低于 0.5 s。
