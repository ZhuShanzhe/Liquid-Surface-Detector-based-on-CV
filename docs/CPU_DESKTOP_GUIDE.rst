RGBD 液深仿真工作台：CPU 离线版使用说明
=========================================

版本范围
--------
本说明对应 Windows x64 的 CPU 仿真桌面入口，使用 V14 正式测量核心与随包模型。
仿真采集采用 Blender Cycles CPU，不是服务器性能报告使用的 EEVEE 渲染器。
本软件用于离线交互展示与后续实地部署的界面模板，不是经过工业真机认证的计量设备。

启动与文件完整性
----------------
使用完整发布包时，无需另外安装 Python、CUDA、Blender 或浏览器，也无需 SSH 连接、
网络服务、USB 相机。桌面窗口内置 Qt WebEngine；本机回环服务只是软件内部通信，
不需要用户手动打开网页。程序计算使用 CPU，不要求 NVIDIA CUDA 独显。

1. 将压缩包完整解压到本地目录。不要在压缩包预览窗口中直接运行。
2. 双击随包的主程序 EXE。首次加载模型与仿真器可能需要较长时间，请等待状态更新。
3. 启动默认自动生成独立空槽图像、建立初始化几何与所需先验，并完成第一帧测量。
4. 当前帧完成前不要强制结束程序；正常退出时会检查是否仍在仿真采集。

必须保留整个软件目录。EXE、内置运行库、模型权重、仿真器、脚本与许可文件共同组成
独立运行包；只复制 EXE 会导致缺失资源。桌面快捷方式可以只指向主程序，但不得移动
或删除其关联资源。发布包的最终桌面交互验收状态以随包验收记录为准。

界面与基本流程
--------------
左侧显示可交互三维场景：左键旋转、右键平移、滚轮缩放，“复位视角”恢复默认观察。
可以分别显示仿真真值、测量点云、估计液面与相机位置。下方 RGB 和深度图来自当前
实际生成的输入，不是事先保存的示例截图；深度图黑色表示无效点。

右侧“安装与标定”设置容器、相机与先验；“运行工况”设置液体及环境。
点击“生成并测量”后应用设置。安装、材质、光学参数或标定模式变化会自动重新标定；
只改变液深、光照等运行工况时复用当前独立标定。“重建先验并测量”可显式重建先验。
数值修改但未应用时显示的仍是上一帧，界面会明确标注。

启动自动先验不等于泄漏当前帧真值：空槽与已知液深先验独立生成，当前帧真实液深只在
测量后用于展示与评分。默认标定采用不超过 10 mm 的高斯扰动，因而不是理想无误差标定。

全部可调参数
------------
安装与标定：

* 容器形状：圆柱、椭圆柱、矩形容器。
* X/Y 内尺寸：各 0.2–6 m。圆柱为内直径并自动联动；椭圆为完整轴长；矩形为完整内宽/内长。
* 容器内高度：0.1–9.8 m。
* 相机到底面距离：界面候选输入 0.2–10 m，相机实际必须至少高出容器口 0.1 m。
* 相机顶部偏心 X/Y：各不超过对应半径或半宽的 25%，保持竖直俯视。
* 自动构图：联动相机高度和 54°–100° 水平视场，并为完整容器口留边。
  若在 10 m 和最大视场内仍无法构图，直接提示调整尺寸，不隐藏越界。
* 初始化先验误差：固定 10 mm 高斯误差或理想标定诊断。前者为零均值截断高斯，
  截断前标准差约 3.33 mm，超出 ±10 mm 的噪声重新抽样；不裁剪测量结果。

运行工况：

* 液体类型：普通漫反射、均匀透明、均匀半透明；由操作人员在初始化时确认。
* 实际液深：0–9 m，不能超过容器高度；正式测试液深范围是 0.10–9 m。
  低于 0.10 m（包括空槽）只作诊断，不沿用正式报告指标。
* 环境光照：2%–100%；眩光：0%–100%。它们是仿真控制强度，不是实测 lux。
* 漂浮物：0–24 个；形态及位置由内置场景构造器生成。
* 液面起伏：0–120 mm，且不能超过液深的 30% 或剩余容器高度的 50%。
* 深度缺失：0%–50% 的控制设定；不等价于最终本帧实测液面缺失率。

透明类光学设置（安装页折叠区）：

* 折射率：1.31–1.45；表面回波权重：0.03–0.12。
* 半透明消光系数：0.02–0.08 /m；散射强度：0.08–0.25。
* 清透明路线不使用半透明散射设置。物性仅进入仿真器，不直接作为测量逆解的正确答案；
  改变这些参数会生成新的独立 5 帧先验来辨识。

界面允许的参数范围不代表所有组合都已经完整性能测试。已发布报告的实际相机到底面
样本约 3.532–9.999 m，容器 X 半径/半宽 0.3–1.5 m，Y/X 比 0.65–1.45。
超出已发布采样边界会标为探索，而不是承诺同样通过率。

功能边界与输入跳过
------------------
普通液体可以组合已经接入的低照、眩光、起伏、漂浮物和部分深度缺失模块。
透明/半透明限于均匀、平整、无遮挡液体，不开放与漂浮物或起伏的组合；它们与光照、
眩光或缺失联合使用时属于探索配置，不直接沿用已发布单场景性能。

视觉模型仅用于需要时的漂浮物最高高度估计，不替换液深几何核心。
深度缺失超过 50%、漂浮物支撑不足、有效液面/相位证据不足等不合格输入会跳过，
不执行分类与测量，也不计入性能统计。不能通过按估计误差大小筛选测试帧。
当前仿真资格审查利用独立可见性标签；未来真机部署必须接入真实可观测性审查。

目前不包含真实相机 SDK、自动硬件标定、泵阀/PLC 控制、多传感器联锁或安全认证。
不能用于工业安全联锁。漂浮物最高高度仍有漏检和尾部误差风险。

读懂结果
--------
所有高度均相对于容器内底面，不是相机到液面的距离。
“代表液面高度”与“最高高度”分开显示；没有漂浮物或起伏时最高高度不适用。
测量结果不强制归零、不裁剪。当前帧真值只用于右侧对照和误差计算。

仿真对照容差沿用：普通液深 max(20 mm, 2% 实际液深)；起伏液面代表高度与最高高度
max(50 mm, 5% 对应实际高度)。分类评分不等于计量置信度；是否选中标签组合不是唯一
通过标准，主要看实际测量误差。界面显示“本帧容差内”不代表现场计量认证。

CPU 时延与验证范围
-----------------
界面分别显示“测量计算”“仿真采集”“初始化”。不应把渲染时间当作模型推理时间，
也不应把服务器 GPU 的延时结果套用到本机 CPU。

当前在 Intel Core Ultra 9 285K（24 核）上的 12 个 CPU 功能冒烟用例观察到：
测量计算约 34–774 ms，仿真采集约 2–2.6 s，
复用标定时总体约 3 s，含重标定约 5–7 s。这只是小规模功能与迁移检查，不是完整
性能认证、最大耗时承诺或所有场景分布统计；计算尾部已经出现超过 0.5 s 的用例。
不同 CPU、首次模型加载、系统负载和工况都会改变耗时；普通低配电脑可能明显更慢。

Cycles CPU 与原 EEVEE 的 RGB 光照、材质和渲染表现可能不同。虽然测量算法及权重
保持同一来源，原 EEVEE 数据上的通过率与误差不能直接成为 CPU 版本的精度声明。
CPU 渲染链路和桌面封装需要独立验证，Qt 桌面交互验收不能用源码冒烟测试代替。

开发者可运行 ``scripts/desktop_launcher.py --gui-self-test``，配合 ``--blender``、
``--work`` 与 ``--output`` 指定本地资源和证据位置。该模式实际启动 Qt 窗口并生成
默认首帧，检查 RGB/深度图、Canvas、数值回显、安装/工况切页，保存两张应用自身窗口
截图和 JSON 后退出。超时或检查失败报告非零退出码，不把静默退出当作验收成功。
它仍只验证默认安装的 GUI 闭环，不替代完整工况回归或最终 EXE 搬移验收。

保存记录与排查问题
------------------
通过桌面“文件”菜单可导出当前测量 JSON，也可打开本次数据与日志目录。
默认位置是 ``%LOCALAPPDATA%\LiquidDepthSimulation``，每次会话在 ``session-日期时间``
目录下保存 ``desktop.log``、标定记录、输入图像/深度和测量结果。日志与新采集不写回
只读软件资源目录。原始仿真数据会占用磁盘，应在退出程序后按明确会话目录归档或清理。

* 提示找不到 Blender 或模型：确认完整解压，未只复制 EXE；不要删除资源子目录。
* 初始化较慢：等待本帧完成，查看状态与日志，不连续启动多个实例争抢 CPU。
* 提示安装或液深冲突：调整容器、相机、液深和波幅；不要绕过校验。
* 显示输入不合格：查看资格原因，减小缺失/遮挡或调整构图；这是跳过，不是输出为零。
* 图形窗口无法加载或程序异常：保留本次 ``desktop.log`` 与测量 JSON 供排查。
  桌面仍需系统显示驱动正常；没有 CUDA 不等于没有任何图形显示依赖。

第三方资源与后续部署
--------------------
Blender、Qt、PyTorch 等第三方组件的许可与通知随发布包提供，迁移或分发时应保留。
当前 EXE 是仿真模板。迁移到工业现场需要替换输入适配层，连接实际 ToF 数据与标定流程，
保留模块边界、输入资格判断和结果记录，并单独完成真实场景精度、稳定性和安全验证。
