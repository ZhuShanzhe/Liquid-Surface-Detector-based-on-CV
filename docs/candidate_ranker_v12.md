# V12：候选排序、全不可靠识别与条件置信度

日期：2026-09-15。范围：仿真算法研究；不自动替换工业面板默认路线。

## 本轮问题

V11 提高了四候选中存在正确液面的比例，但旧选层器继续叠加单深度先验距离、液面身份、存在性与尺度分数，导致大量正确候选无法成为有效输出。V12 固定 V11 control 的四个深度，只学习如何选、何时不应输出，不通过增加候选数抬高指标。

这里的深度是相机光轴方向深度 z，不是相机到点的欧氏射线长度，也不是相对容器底部的液深。容差沿用 `max(5 mm, 0.02*z)`；最终液深仍需容器标定、液面几何与传播误差验证。历史文档中的“camera-ray”措辞应按此轴向深度口径理解。

## 模块

- **候选质量评分**：对每个候选监督“是否在真值容差内”，在存在正确候选时使用多正例排序损失。没有正确候选时不强行把最接近但仍错误的一层当正例。
- **全不可靠分支**：监督四候选均不满足容差的情况；推理不读取真值。候选质量与全不可靠分数结合，形成待校准的输出分数。
- **保持候选置换对称**：四层使用共享评分器；交换候选排列不改变选择出的深度。物理层存在性、液面身份与误差质量分别作为输入/目标，不混为同一个概率。
- **软几何证据**：利用已知相机内参、预测法向与候选深度，计算邻域候选点相对当前局部切平面的距离；在邻居四层中寻找支撑，不假设相邻像素的同编号层对应同一个界面。使用 2 和 8 像素两个邻域尺度，以软特征输入，不作硬平面拒绝。
- **条件置信度拟合**：在单独校准序列上，用固定 32 分箱及加权单调回归拟合“当前所选点正确”的概率映射；不是对任意相机或域偏移均有效的概率保证。

几何模块匹配仿真器的 Blender 相机坐标约定：x 向右、y 向上、z 向后，深度值为正的前向光轴距离。部署到常见 OpenCV 相机坐标时，必须同步转换射线与法向。只读取内参；不将仿真相机位姿、容器液位、容器底面真值或真实液面法向作为模型输入。局部法向来自冻结网络，并不是真值。

几何一致性不能证明物理正确：完整但错误的容器底面同样可能很平整。波动液面只能提供局部近似支撑，不能据此强制整个液面为平面。本轮不加入新的时间记忆或完整折射光路。

## 数据和实验隔离

- 原清单：`liquid-sim-v3-calibration-top-12000/manifest_multilayer_v4_refined.csv`。
- 使用 transparent、translucent、multilayer、compound 四场景。训练 3,899 帧。
- 原验证集按 sequence_id 的 SHA256 对 3 取模拆分：选轮次 172 帧、校准 162 帧、选输出门限 147 帧。三部分与本轮训练序列无交集。
- 需要注意：V11 候选模型此前选权重时使用过整个旧验证集。因此该拆分实现的是本轮训练/校准/门限分工，不应宣传为整个历史开发流程完全未接触的校准集。
- 新留出集 64 帧，每帧独立序列；四场景各 16 帧、四距离区间各 16 帧，8 种容器形状各 8 帧，3 种传感器代理。保持顶部部署为主，实际相机仰角约 43.2°–86.7°。
- 新留出集只更换随机场景采样，不是新物理渲染器或真实传感器；RGB 使用现有 Eevee，深度仍是现有几何标签与传感器代理。不能据此证明真实透明液体的折射测量已解决。
- 原测试 486 帧保留为历史对照；新增 64 帧作本轮未用于训练、校准、门限选择的复核。样本量不足以作工业稳定性认证。

## 对照与训练流程

第一轮对照：仅候选数值、局部图像与冻结输出特征，分别训练 rank_only 和 geometry。观察到验证效果不稳定后，在**尚未查看本轮测试结果**时增加第二轮 feature-context 对照：加入冻结主干的 24 通道深层特征与全局池化上下文。第一轮所有结果原样保留。

每组 6 轮、每轮 4,096 次有放回采样，batch=8；按场景与相机距离区间联合均衡；AdamW，初始学习率 3e-4，余弦下降，种子 20260916。对约 25% 训练样本加入原 V11 的 3%–20% 有符号有效深度偏差代理。深度候选随输入变化，但生成器参数始终冻结。没有新增专门的 95%–100% 缺失恢复目标。

选轮次只看对应验证子集的分场景宏平均首选候选命中率；校准映射只用校准子集。输出门限固定扫描 0.3/0.4/0.5/0.6/0.7/0.8/0.9/0.95，在选门限子集上要求：

1. MAE 不超过同子集 V9.1 的 1.05 倍；
2. AbsRel 不超过 `max(3%, V9.1)`；
3. 容差通过率至少 `max(50%, V9.1-1个百分点)`；
4. 有效液面像素覆盖不低于 V9.1 减 2 个百分点；
5. 非目标输出比例不高于 V9.1 加 2 个百分点。

满足后最大化“全部真实液面中既输出又正确的比例”。无合格门限则记录 null，不放宽规则；该工作点准入不是完整液深工程验收。模型、校准与清单哈希冻结后才进入测试，测试结果不用于该轮门限回调。

## 指标说明

- 首选候选命中率：在全部真实有效液面像素上统计选层是否正确，尚未拒绝，区分排序能力与输出筛选。
- Oracle 候选命中率：四层中存在正确候选，仅作离线参考；冻结候选后不应因排序器而变化。
- 覆盖率与容差通过率必须同时报告；低覆盖上的小 MAE 不算整体改进。
- 全无正确候选时的误接受率：分母是这些真实液面像素，分子是其中仍被最终门限接受的像素。与“所有输出中有多少错误”的比例不同。
- ECE/Brier：在预测液面区域上，所选候选是否在真实容差内作为标签，非真实液面输出作为错误。旧模型分数未作本轮概率校准，相关数值仅是同口径诊断。
- 固定 +5% 深度输入偏移压力测试检查域偏移；清洁校准映射在此条件下不保证可靠。

## 复现与产物

模块：`src/liquid_depth/models/candidate_ranker.py`。

数据生成：`scripts/generate_candidate_holdout_v12.py`，通过服务器 Blender 后台模式启动，输出新目录，不覆盖旧场景。

训练/测试：`scripts/train_candidate_ranker_v12.py`；`--feature-context` 启用第二轮上下文结构。训练目录默认拒绝覆盖，测试开始后拒绝原目录再次测试，防止隐式更改已冻结结果。当前脚本不实现断点续训，失败重跑使用新实验目录。

```bash
python scripts/train_candidate_ranker_v12.py \
  --base /root/autodl-tmp/liquid-depth-artifacts/training/universal-liquid-v9-1-transparent-multilayer/best.pth \
  --candidates /root/autodl-tmp/liquid-depth-artifacts/training/liquid-candidate-v11-factorial-20260915/control/best.pth \
  --manifest /root/autodl-tmp/liquid-depth-data/synthetic/liquid-sim-v3-calibration-top-12000/manifest_multilayer_v4_refined.csv \
  --fresh-manifest /root/autodl-tmp/liquid-depth-data/synthetic/candidate-ranker-v12-fresh-20260915/manifest.csv \
  --run-dir /root/autodl-tmp/liquid-depth-artifacts/training/candidate-ranker-v12-context-20260915 \
  --feature-context --epochs 6 --samples 4096 --phase train
```

训练结束冻结选择后，先用相同参数执行 `--phase calibrate-baseline`，拟合并冻结“旧选层器不变，仅校准其置信度”的额外对照；随后执行 `--phase test`。不带 feature-context 的第一轮目录为 `candidate-ranker-v12-20260915`。所有路径中的日期是执行日期，数值随机种子只是实验标识。

只校准旧选层器的对照使用相同的校准/门限子集，仍保留旧先验硬支撑限制。它在两个实验目录均未找到合格验证工作点；不得根据测试集给它重新选择最优门限。用于诊断时保留固定 0.5 的扫描结果。

## 实验完成结果

四个评分器均完成 6 轮训练。第一轮两个轻量评分器没有合格验证工作点；第二轮两个上下文评分器均在验证子集选定 0.4，最佳权重均来自第 1 轮。后续训练未持续改善验证首选命中率，说明仅增加轮次没有解决目前瓶颈。测试前已冻结全部权重、校准和门限，没有根据测试结果再训练或改门限。

### 不确定度与全不可靠识别

上下文 rank_only 在选门限验证子集上，校准前 ECE 21.13%、Brier 0.2760，校准后分别为 3.75%、0.2272。旧测试 ECE 为 3.99%，但新留出集升至 11.84%；几何版本对应旧测试 4.05%、新留出 12.19%。映射对旧分布有用，不具备跨分布可靠性保证。

按全不可靠分支自身 0.5 分类门限，上下文版能识别旧测试 42.34% 的“所有候选均错误”像素，同时误拒 6.17% 的“存在正确候选”像素；新留出分别为 27.20% 和 5.82%。仍漏掉多数全不可靠情况，不能作为独立安全保护。

按最终 0.4 输出门限，在所有候选均错误的像素中，旧测试仍有 29.53% 被接受、新留出有 33.12% 被接受（几何版 31.67%/35.01%）。V9.1 对应 43.75%/47.17%，但候选池和接受覆盖不同，不能只按该单项比例宣称安全性整体提升。

### 抽样不确定性与延时

以序列配对 bootstrap 2,000 次、种子 20260916，对比 V9.1 的全目标正确输出率增量：旧测试上下文版 95% 区间 [-1.93,3.09] 个百分点，几何版 [-0.08,3.82]；新留出分别 [-2.79,3.25]、[-1.17,3.95]。均包含零，**总体收益没有得到稳定的统计支持**。旧多层透明几何版区间 [0.49,8.25]，但在新留出不保持，且存在多重探索比较，不作为全面成功证据。

RTX 5090 常驻 GPU 输入、batch=1、320×180：上下文版 P50/P95 约 4.46/4.51 ms，几何版约 6.08/6.47 ms；V9.1 约 4.04/4.26 ms。几何额外约 1.6 ms（P50），目前不是主要瓶颈。排除相机采集、CPU 预处理、时间融合、最终几何液深计算与界面，不能直接宣称整机延时达标。

## 验证、结论与后续顺序

204 项自动测试通过，13 条已有警告。覆盖候选置换对称、冻结深度一致性、绝对/倾斜平面几何、无正确候选不制造正例、空标签、单调校准、冻结后禁止回调。新仿真数据检查 64/64 完整、无错误；两个实验目录均生成 `test_complete.json`。

**决定：四个模型和校准器保留为研究产物，默认运行模型、面板与现有投票路线不替换。上下文无几何版本作为下一轮研究对照，几何模块仍按需启用，不能直接推广为默认升级。**

目前原因与下一步：

1. 候选池和首选正确率差距仍大；简单独立评分并没有充分解决候选之间的竞争与界面身份。下一轮优先考虑候选集合交互、成对好坏排序，以及保留原选层证据的残差式重排，而不是继续堆叠层数。
2. 局部平整度对液面、透明壁、底面都可能成立。需要容器边界、已知标定点、历史可靠点等场景锚点，不能把法向一致当成独立的真实深度证据。现有结果不足以归因为纯硬件不可观测，也不能认为都是模型容量不足。
3. 全不可靠分支漏检多，干净校准遇到偏移会失准。下一轮应加入按量程/输入质量分组的校准、域外检测，以及专门的错误回波负例；所有门限仍在独立校准/选择集冻结。
4. 当前新场景已作为测试查看，若后续用于开发或训练，必须再生成另一批新种子留出集。应扩大容器、距离、液深与退化强度的组合，优先补充模型无法区分液面/底面的负例，而不继续对同一测试集逐轮调参。
5. 不再将“候选中存在正确答案”或“拒绝后少量点很准”作为项目完成条件。下一轮以首选命中率、共同评估口径下的风险—覆盖关系，以及跨新场景保持性作为主要验收。
