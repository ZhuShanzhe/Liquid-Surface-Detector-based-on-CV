正式 v2 ToF 复合证据修复（2026-10-20）
==================================

定位与范围
----------

用户已确认将本模块选为正式 v2 默认数值链路；measure_tof.py 与统一入口均已接入。
旧 PDF 保留历史原文，不伪造重算统计；新的后续训练实验不自动替换此基线。
仅用于固定相机、已标定空槽几何的普通不透明液体及已有低照、眩光、起伏、
0--50% 液面深度缺失、漂浮物两因素组合。透明/半透明相位路线不启用本模块。
不是工业精度认证，不承诺三个以上因素组合或极端失效。

开启
----

在项目目录执行：

::

  LIQUID_PYTHON=/root/autodl-tmp/envs/liquid-depth/bin/python \
    bash scripts/launch_scene_console.sh --port 8766 --compound-repair

数值修复默认开启。诊断旧版可使用 --legacy-geometry。需要同屏对照时使用另一端口，不中断已有服务。
Python 可设置 ``UnifiedToFMeter(..., compound_repair=True)``；
初始化后可调用 ``warm_optional_peak_models()``，仅预热模型内核、丢弃全部预测，
不生成测量值、不参与标定或时序先验。控制台在开启修复时自动执行该步骤。
``ToFObservation.capture_validity`` 可传与深度对齐的布尔有效回波图。
SDK 原生有效性、幅值或质量标志应由采集适配器解析，不接受由仿真真值生成的运行时掩码。

独立模块
--------

1. native_tof_input_validity：输入无效性审计。保留有限、正数且不低于相机最小测距的输入。
   仿真档案默认最小测距 0.08 m，可用 CompoundRepairPolicy 调整；这是相机测距下限，
   不是液深下限。无 10 m 硬裁切，10 m 附近读数正常处理。
2. wet_dry_identity_evidence：基于独立空槽与当前回波，剔除几何上属于侧壁/容器外的
   液面证据，再比较持续空槽返回与连续湿表面候选。覆盖率用容器坐标空间格计算，
   而不是较宽的槽口图像包围盒。证据足够且与旧估计有显著差异才替换；
   不调用 RGB、视觉语义、当前真值或已知实际液深。空槽不强制归零。
3. supported_highest_height：局部最高包络必须有原始点邻域支撑。
   漂浮物视觉仅用于最高高度，候选还要通过实际内部几何、测距有效性、局部拟合残差和
   高度见证点检查。模型拟合不增加独立观测点数量；不靠最终输出裁剪提高成绩。

视觉复用
--------

复合修复开启时，不先执行一遍旧最高点视觉推理再重复执行新推理；
直接复用预载的 V8/V5 最高点模型。只有新包络完全没有支撑时才延迟运行旧视觉回退。
液深主计算不依赖视觉，分类器仍为冻结 V4，本轮未重新训练或按测试结果修改阈值。
分类仍可能漏检小漂浮物；语义概率不等于回波可靠性或计量置信度。

仿真输入修复
------------

render_scene_console.py 的眩光只选择 glare，不再隐式选择会叠加多层折射、散射偏置和
ToF 多径的 compound。射线未命中的背景始终保持无效，不向零深度加噪生成近相机点。
新增 capture_valid.npy 和 offline_return_origin.npz；后者仅离线审计，不进入推理。
波动和漂浮物通过几何构建，RGB 光照与深度代理仍不是经真实相机标定的数字孪生。
现有低照代理还会附加 ToF 缺失，不能把它解释为真实主动 ToF 在暗处必然退化。
