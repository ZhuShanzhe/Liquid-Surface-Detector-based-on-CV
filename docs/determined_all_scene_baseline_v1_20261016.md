# 全场景确定版与 V8 漂浮物视觉引导

2026年10月16日确定。本版作为下一阶段远距浅液位研究的固定基线，其他问题仅记录，不启动修复、训练或新模块选型。本次只统一接口、回放统计和封存，不修改已有测量算法。所有结果为仿真研究，尚未获得真实设备现场计量资格。

## 版本和场景边界

统一入口为`liquid_depth.determined_scene_meter.DeterminedSceneMeter`，无USB命令行入口为`scripts/measure_determined.py`，场景与后续工作约束记录在`configs/determined_scene_routes_v1.json`。场景由操作者明确选择，未实现自动可靠分类。

| 场景 | 当前液深计算 | 最高高度 | 视觉应用 |
|---|---|---|---|
| 普通漫反射 | 空槽建模和冻结对称候选几何 | 原几何包络 | 禁止 |
| 部分深度丢失 0%–50% | 同一冻结对称候选几何 | 原几何包络 | 禁止 |
| 低照 | 同一冻结对称候选几何 | 原几何包络 | 禁止，不自动提亮 |
| 眩光 | 同一冻结对称候选几何 | 原几何包络 | 禁止 |
| 不平整液面 | 同一冻结几何的代表液深 | 原V11默认包络修复 | 禁止 |
| 漂浮物 | 同一冻结几何，不受视觉改写 | 默认几何；显式开启后V8选定策略 | 只用于最高高度 |
| 均匀透明 | 一帧空槽加四帧已知液深，左右目图像相对配准，baseline_v32 | 本入口不扩展最高物体功能 | 不启用V8 |
| 轻度均匀半透明 | 同一五帧预算，对称配准midpoint_dense | 本入口不扩展最高物体功能 | 不启用V8 |

V8选定策略不是所有传感器都使用新的学习头：ToF和结构光沿用验证选定的V5分支，主动双目使用V8分类、连续高度校正和风险排序。双目策略为身份门槛0.7、至少8点和2个空间格、风险上限250mm、风险权重0.5、最高实例差距权重0，失败回退V4。`research`、`no_rank`和V9不属于当前确定入口。

多层透明、底纹不可见、强散射作为透明链路、超过50%的深度丢失、持续移动相机和极端复合干扰不在确定版的适配承诺中。强散射液体只有在传感器工作波段能获得普通表面返回时才可按普通场景处理，不能仅按肉眼外观判断。

## 实际调用关系

不透明类入口依次调用`floating_rank_application_v8.from_empty_geometry`、`FloatingPeakOnlyMeter`和`HybridSceneMeterV2`。所有液深先由`FrozenSymmetricGeometryMeter`调用原样冻结的`SymmetricVisualMeter`无视觉分支计算；最高高度由`UnevenSurfaceMeter`给出，仅在漂浮物且明确授权时允许V8辅助结果替换最高高度。V4名称在此仍表示未改动的输出范围门控，不表示当前辅助后端退回了V4。

冻结对称几何内部仍调用`FormalSceneMeter`取得无峰时的回退，但有候选时按自身同等地位评分选择底面或液面。因此，早期正式三场景的V64/V67/V72结果不能直接作为现在的主液深性能。当前构造函数未提供V72量化档案，也没有默认接入V37四帧融合、V39公共偏置模型或V40空槽空间去噪；这些代码保留为历史候选，不因封装而启用。

透明类入口则直接调用`FormalSceneMeter.from_five_priors`和`FivePriorImageMeter`。它利用可见底纹响应与已知液深曲线，不是把透明液面失效点云补成真实返回。先验只在初始化使用；当前测量帧之间无记忆。

本版不强制零位吸附、不按容器容量或10m裁剪液深、不以精度门槛拒绝测试帧。现有算法的有限正深度、容器范围、候选生成和物理支持条件仍保留，并非取消全部输入有效性检查。

## 统一指标和证据分组

液深均相对容器内部底面；波面以物理面积平均液深评分，最高高度以物理网格最高顶点评分。液深容差为`max(20mm,2%实际液深)`，最高高度容差为`max(50mm,5%实际最高高度)`。MAE、P95和最大误差只统计有限数值；覆盖率与全帧通过率以全部对应帧为分母，未输出不是零误差。相对误差分母为实际液深或实际最高高度，空槽不定义相对误差。

误差分档为0–5、5–20、20–50、50–100和超过100mm；相对误差为0–1%、1–2%、2–5%、5–10%和超过10%。零液深、远距空槽与非零浅液位分别列出。默认远距浅液位分层为相机到底面垂距至少6m且`0<H≤1m`；只供事后统计，不是用真实液深选择运行算法的条件。

各数据组独立列示，不计算跨场景加权总准确率：

| 证据组 | 数据范围 | 本轮行为 |
|---|---|---|
| 六场景回放 | 既有种子202610154229，198安装、396帧、480×270，每类66帧 | 实际调用统一入口；液深与既有无视觉结果逐帧校验，非漂浮物最高高度与既有几何包络校验 |
| 普通与受控缺失网格 | 既有种子202610141101，99安装尝试、普通396帧，缺失样本按原协议重建 | 实际调用当前入口，分液深、传感器和缺失率统计；输入几何失败与范围外样本单列 |
| 透明与半透明完整记录 | 既有48配置、8016组图像，原生底纹宽128/160像素 | 只对既有选定方法重算20mm/2%指标；另以12配置、288帧实际调用接口核验 |
| 漂浮物专项 | 既有种子202610164913，99安装、396帧，其中有漂浮物360帧、干槽36帧 | 复用已核验V8选定策略逐帧记录，分组统计；不是本轮新增独立采集 |

这些集均曾用于历史分析，本轮回放不是新盲测。重复帧、受控删点条件和同图方法结果不等于新增独立安装。传感器是参数化代理，ToF的良好仿真结果不是实机型号优劣结论。初始化错误不在本轮修缮范围；记录错误数量，不伪造修好的先验。

## 其他不足简记

| 问题 | 当前记录和限制 |
|---|---|
| 小漂浮物和错误实例 | V8仍会漏最高物体、选较低物体或混合回波；不将分类分数视为计量置信度 |
| 结构光尾部误差 | V8的结构光仍用V5，最大误差并未因版本名改变而消除 |
| 波面代表液深 | 冻结几何的稳健代表值不严格等于物理面积均值；最高包络不代表被遮挡的真实顶点必然可见 |
| 眩光和低照极端帧 | 有数值不等于证据充分，RGB提亮不能自动修正错误IR返回 |
| 标定和几何范围 | 相机移动、底面/上沿不可观测、轮廓或米制参数错误需重新标定；本轮只记录，不自动修复 |
| 延时与工业输出 | 浮物模型加载、复杂候选和回退可能超过0.5s；统计为算法调用，不含曝光、通信和GUI；未获安全控制资格 |

本轮不为这些问题训练模型、修改阈值或增加替代模块。V9不合并，旧研究代码也不删除，避免破坏对照和修复历史。

## 使用与封存

统一命令行接受一个初始化JSON。普通类JSON字段为`kind=empty_geometry`、`bundle`标定JSON路径、`dry_depth`米制空槽数组路径，可选`max_return_depth_m`，默认沿用原入口10.5m的原始返回档案。10m是应用与测试布置范围，不是将测量值截断到10m。

```bash
PYTHONPATH=src:scripts /root/autodl-tmp/envs/liquid-depth/bin/python scripts/measure_determined.py \
  --scene ordinary_diffuse --initialization /path/to/initialization.json --depth /path/to/depth_m.npy
```

漂浮物场景另外指定`--scene floating_objects --rgb /path/to/rgb.png --enable-floating-peak-vision`，不指定开关时仍为纯几何。其他场景即使给开关也不得执行视觉。

透明类初始化JSON字段为`kind=five_priors`、`calibration`、包含left/right数组的`masks` NPZ、5组left/right图像路径的`prior_images`、5个`known_heights_m`。首个标签为操作员确认的空槽0，其余4个互异且为正；初始化后以`--left`和`--right`给出当前已校正左右目灰度图。五组不是五张单目图，也不允许使用当前测试真值。路径相对于初始化JSON所在目录或使用绝对路径。

封存目录为`/root/autodl-tmp/liquid-depth-artifacts/determined-all-scenes-v1-20261016`。源码、运行依赖索引、权重哈希、分场景及远距浅液位统计、逐帧诊断、输入审计、无USB样例和测试结果随版本保存。既有训练集和原始图像继续留在原目录，不复制数百GB数据。此包是服务器上可复现的确定研究版本，不声称所有工业GUI、相机驱动或另一台服务器已自动完成接入。

8类公开命令行入口烟测均通过，漂浮物开关前后液深一致，其他场景即使传入视觉开关也不执行视觉。完整回归为719项通过、14条既有依赖警告。本轮没有训练、下载新模型、修改旧算法文件或删除旧实验；本地工作副本仅用于整理，最终成果保留服务器。

回放后仅按静态检查整理了新命令行文件一行导入符号顺序，未改执行逻辑；原评估指纹保留，格式前后差异另存`post-evaluation-format-audit.json`，并重新核对公开CLI输出。旧算法与模型指纹继续与此前封存版本比较。
